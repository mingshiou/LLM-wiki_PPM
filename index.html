系統架構：Loop / Graph 流程設計

五階段自動化生成與檢核標準作業程序 (SOP)

本專案建立的 Loop / Graph 流程規範於 AGENTS.md 與 .agents/skills/educational-slides/SKILL.md，解決傳統 LLM 一次性生成容易幻覺、圖文擠壓與死循環問題：

Phase 1

知識庫檢索與覆蓋度稽核

比對 Wiki 條目：≥70% 充足執行；30–70% 提出收斂方案（限補 1 篇）；<30% 邊界阻斷，絕不盲目搜尋。

Phase 2 【強制中斷點】

大綱規劃與用戶對齊確認

生成 10–13 頁大綱並標註引用。Agent 必須停下來等待用戶確認，未經同意嚴禁逕自寫程式碼！

Phase 3

16:9 Reveal.js 規格生成

依據 Skill 樣板：鎖定 1280×720，Body ≤ 520px，自然去方框化，平滑貝茲曲線，真實受體膜拓撲。

Phase 4 【自動檢核與熔斷】

Self-Linting 自動自我審查

執行 6 大檢核清單（語言、幾何、去框、科學精度、引用、備忘稿）。最多自動修復 2 次，超限觸發透明回報。

Phase 5

雙軌交付與系統日誌

產出 HTML 簡報與同步 Markdown 講義檔，自動更新全域 index.md 與 log.md 運作紀錄。

為什麼這樣設計？（SOP 設計核心哲學）
1. 邊界收斂（Decoupling）：將「文獻擴充」與「簡報生成」解耦，避免簡報做到一半無止盡地去找外部論文，造成任務發散（Scope Creep）。
2. 大綱守門員（Human-in-the-loop Gatekeeper）：在寫幾百行 HTML 前先確立邏輯架構，大幅減少後續重構成本。
3. 2 次修復熔斷機制（Circuit Breaker）：防止模型在自我檢核失敗時陷入「修復 → 失敗 → 再修復」的無限死循環，保護 Token 預算並及時求助人類。

2. 深度反思：哪個節點最常出錯？如何前置防禦？

⚠️ 哪個節點最常出錯？
「SVG 向量圖的幾何比例失真」 與 「資訊過度方框化（Box-in-a-box syndrome）」 最常出錯！
LLM 在撰寫 SVG 時，無法即時在物理螢幕上「看見」渲染尺寸，常將 4 欄文字塞入狹長 ViewBox 中，導致字體變形或疊壓；同時 LLM 習慣用 <div class="card"> 包裹每一段文字，造成視覺疲勞。
🛡️ 我們如何將檢核前移，並修改了哪些 Workflow？
1. 技術解耦（CSS Pipeline 替代 SVG 文字）：在 Skill 中規定「流程性文字」必須採用 HTML/CSS Flexbox 排版，SVG 僅負責繪製幾何結構與平滑曲線，從根源根除字體擠壓。
2. 建立 16:9 幾何高度硬指標：規範主內容區高度預算嚴格 $\le 520\text{px}$、圖形長寬比 $\ge 4:3$ 或 $16:10$。
3. 去方框化排版哲學：規定非並列對等比較項一律自然流動，提升學術呼吸感。
4. 確立 2 次自動修復熔斷機制：如果 2 次 auto-fix 仍有版面衝突，立即觸發透明回報，由人類決策是否拆頁或刪減文字。
